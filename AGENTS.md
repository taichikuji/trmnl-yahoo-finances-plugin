# Project working agreement

- Commit every iteration before ending work, including an unfinished but useful checkpoint. Describe unfinished work and any failing checks honestly in the commit message.
- Preserve the project's history. Do not amend, squash, rebase, or discard earlier commits unless the user explicitly asks.
- Keep changes small and commit messages concrete so earlier decisions and working versions remain easy to find.
- Follow the existing TRMNL repositories' commit style: lowercase Conventional Commit prefixes (`feat:`, `fix:`, `refactor:`, `style:`, `docs:`, `test:`, `chore:`), followed by a short imperative subject without a final period. Add a body only when it explains a meaningful behavior or validation detail. Examples: `refactor: group related pet display values`, `docs: regenerate plugin previews from current templates`.
- Use TRMNL Framework components, typography, and utilities for layout and presentation. Add custom CSS only when the framework cannot express the required behavior; verify previews with the pinned framework stylesheet and its actual fonts.
- Prioritize visual quality in this order: TRMNL OG, TRMNL X landscape, OG B/W/R/Y, then X portrait. Keep the UI simple and retain readable monochrome cues when adding color.
- Use automatic palette-aware direction cues: arrows/signs in grayscale, yellow gain highlights and red losses on B/W/R/Y, green/red on palettes that support them. Candle direction is open-to-close; the headline indicator follows the selected return baseline.
- Keep the current presentation: prominent price, plain ticker text, and source details above the chart. The user chose this combination after comparing layouts.
- Keep shared UI preparation, styles and reusable Liquid templates in `TRMNL/src/shared.liquid`. Each of the four nonempty view files owns its layout and type sizes, rendering those common components with explicit parameters. Keep presentation in Liquid; retain Serverless for provider/FX requests, validation, saved state, chart math and timezone-aware numeric/date formatting where moving it would add complexity. Preview all four layouts on OG, X and OG B/W/R/Y in both orientations before claiming support.
- Use the registered `trmnl` MCP server to inspect and update this plugin on TRMNL. The user authorized plugin management through that server. `TRMNL_MCP_API_KEY` comes from the ignored project `.env`; never print or commit the credential or authenticated server URL. Generate an import ZIP only when explicitly requested. Automatic Git push and TRMNL deployment on push are not configured yet; keep making local commits for each iteration.

Reference projects: [TRMNLGotchi](https://github.com/taichikuji/trmnl-tamagotchi-plugin), [HTTP Pets](https://github.com/taichikuji/trmnl-http-pets-plugin), and [TMB](https://github.com/taichikuji/trmnl-tmb-plugin).
