# Project working agreement

- Commit every iteration before ending work, including an unfinished but useful checkpoint. Describe unfinished work and any failing checks honestly in the commit message.
- Preserve the project's history. Do not amend, squash, rebase, or discard earlier commits unless the user explicitly asks.
- Keep changes small and commit messages concrete so earlier decisions and working versions remain easy to find.
- Follow the existing TRMNL repositories' commit style: lowercase Conventional Commit prefixes (`feat:`, `fix:`, `refactor:`, `style:`, `docs:`, `test:`, `chore:`), followed by a short imperative subject without a final period. Add a body only when it explains a meaningful behavior or validation detail. Examples: `refactor: group related pet display values`, `docs: regenerate plugin previews from current templates`.
- Use TRMNL Framework components, typography, and utilities for layout and presentation. Add custom CSS only when the framework cannot express the required behavior; verify previews with the pinned framework stylesheet and its actual fonts.
- Prioritize visual quality in this order: TRMNL OG, TRMNL X landscape, OG B/W/R/Y, then X portrait. Keep the UI simple and retain readable monochrome cues when adding color.
- Use automatic palette-aware direction cues: arrows/signs in grayscale, yellow gain highlights and red losses on B/W/R/Y, green/red on palettes that support them. Candle direction is open-to-close; the headline indicator follows the selected return baseline.
- Keep the current presentation: prominent price, plain ticker text, and source details above the chart. The user chose this combination after comparing layouts.
- Keep shared UI preparation, styles and reusable Liquid templates in `TRMNL/src/shared.liquid`. Each of the four nonempty view files owns its layout and type sizes, rendering those common components with explicit parameters. Keep presentation in Liquid; retain Serverless for provider/FX requests, validation, saved state, chart math and timezone-aware numeric/date formatting where moving it would add complexity. Preview all four layouts on OG, X and OG B/W/R/Y in both orientations before claiming support.
- Use the registered `trmnl` MCP server to inspect and update this plugin on TRMNL. The user authorized plugin management through that server. Keep MCP credentials in private client configuration; never print or commit credentials or authenticated server URLs. Generate an import ZIP only when explicitly requested. The user authorized pushing this project to `https://github.com/taichikuji/trmnl-yahoo-finances-plugin`, tracked as `origin/main`; commit and push each iteration while preserving history. TRMNL deployment on push is not configured; continue using MCP for hosted updates.

Reference projects: [TRMNLGotchi](https://github.com/taichikuji/trmnl-tamagotchi-plugin), [HTTP Pets](https://github.com/taichikuji/trmnl-http-pets-plugin), and [TMB](https://github.com/taichikuji/trmnl-tmb-plugin).

Repository conventions: keep the public root to `.github/`, `.gitignore`, `LICENSE`, `README.md`, `TRMNL/` and `scripts/`, as in the reference repositories. Agent instructions stay local and ignored. Put setup/development documentation in `TRMNL/README.md`, use `TRMNL/.trmnlp.yml` for an offline native preview, and run tests directly with Node. Keep only the helpers actually used by tests and previews. Keep docs focused on installation, usage and necessary maintenance; do not narrate iterations or duplicate simple configuration values. Routine config changes do not need README edits.

Branding convention: create original artwork using the same transparent orange `#E76F55` as HTTP Pets, TMB and TRMNLGotchi. The user wants a simple rising stock line, not an imported or adapted third-party icon. Keep only the responsive asset in `TRMNL/media/icon.svg` and reference `media/icon.svg` from settings.yml. Do not create size-specific icon copies. Check the reference projects before choosing asset names, colors or presentation conventions.
Current MCP limitation: source imports ignore icon assets and omit the icon reference on readback. A dashboard icon upload is separate; never claim the live listing icon changed without verifying it.
Repository preview convention: generate synthetic, visibly labelled sample renders with scripts/preview.cjs; commit lossless WebP files under TRMNL/media using the reference projects' preview_full, preview_half_horizontal, preview_half_vertical, preview_quadrant, preview_trmnl_x, preview_trmnl_x_portrait and preview_bwry names. Keep live account snapshots out of public preview assets.

The user uploaded the previous icon to trmnl.com. The replacement original icon still needs a dashboard upload; MCP source imports cannot replace it.

Readability: default chart/supporting text is 12 px, with a native 21 px company name and 38 px price on OG full screen. Keep user-selected font sizes available and verify actual computed sizes plus bounds on all slots. Stock logos are absent from the normal Yahoo chart response; do not add guessed logo URLs or another provider/authentication flow without a user request.

Copy: keep the user's tagline "watch line go up" and otherwise use plain, factual descriptions and concise setting labels. Accept Yahoo Finance symbols, plain or URL-encoded; do not add TradingView aliases or exchange mappings. Default refresh interval is 15 minutes for free accounts; 5 minutes requires TRMNL+. This is the minimum time between eligible updates, not a scheduled request loop: actual updates follow TRMNL's on-demand device/playlist cadence.
